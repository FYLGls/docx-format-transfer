# 设计文档：修改顺序与确认 UX 的决策依据

配套操作文档：`skill/references/apply-order.md`（执行细则）、`skill/references/ux-playbook.md`（交互细则）。本文记录**为什么这么设计**，以及各角色视角的取舍。

## 1. 为什么分页类修改必须放最后、自上而下单遍

排版修改存在依赖链：字体/字号/行距/图片尺寸 → 决定每块内容高度 → 决定分页位置 → 决定"表是否跨页、题注是否孤立、续表出现在哪"。若在改字体的同时处理分页，后面的字体修改会让前面的分页决策全部失效，形成"改一处、处处变"的震荡。

因此：
- 阶段 1-3 只做**内容与定义层**修改（含 cantSplit/tblHeader 这类"属性写入"，它们不依赖当前分页状态）；
- 阶段 4 在内容高度定型后，**用真实渲染结果**（LibreOffice → PDF 分页）做一次自上而下的布局决策：keep 绑定、整表不分页 vs 重复表头、孤立题注补强；
- 复渲染复查至多 2 轮：keepNext 可能连锁把内容推得更远，必须有轮次上限防死循环，超限如实报告交给用户。

## 2. 为什么"样式定义层"先于"逐段清理"

Word 格式的优先级是：直接格式 > 段落样式 > basedOn 链 > 文档默认。目标的乱格式大多来自直接格式污染。先覆写样式定义、再清直接格式，一次操作让全部引用段落归位；反过来（先逐段改再改样式）会造成双重维护和不一致。

## 3. 为什么题注用手打+域双方案

- 模板用域（SEQ/STYLEREF）→ 迁移域代码并**预写字面结果**：用户打开即见正确编号，F9 刷新后不变（域自证）。
- 模板手打 → 只能维护章节计数器全文重排。此时交叉引用"如图3-1所示"必须同步正则替换，否则编号与引用脱节——这是数模/论文查格式的高频错误点。

## 4. 为什么"续表"翻译成 cantSplit/tblHeader

"表分页时下页写续表标题"是**渲染时行为**，Word 没有对应机制可写死。等价实现二选一：
- 整表不分页（短表）：全行 cantSplit + 表前 keepNext；
- 跨页重复表头（长表）：首行 tblHeader（每页自动重表头，多数学校认可为续表等价形式）。
不伪造"续表X"文本（分页位置变化后立即变错字）。此局限在确认清单中明示。

## 5. 各角色视角的边界取舍

| 角色 | 结论 |
|------|------|
| 用户调研 | 核心痛点是"漏项"而非"改不动"→ 清单必须全、证据必须可视化（12 张图 11 张 14cm） |
| PM | v1 做 docx 全闭环；内容级改写（参考文献字段重排、图内文字、OLE 公式）只检测不修改；原件只读、输出新文件、幂等可重跑是底线承诺 |
| 架构 | 五层流水线（提取→归纳→映射→应用→验证），格式档案 IR 格式无关，为 LaTeX/PDF 留两端替换空间；脚本管确定性、模型管语义裁决 |
| QA | 20 场景夹具+ground truth 自动评测；内容零损坏断言（除题注编号/域结果外逐字相等）是每次回归的硬门槛 |
| 运营 | SKILL.md 中文触发词覆盖"套模板/按模板改格式/格式体检"；异常路径（加密、.doc、缺维度）都有话术，不静默降级 |

## 6. 风险登记
1. **WPS/Word 渲染差异**：页码格式以域 instrText 为准（WPS 忽略 pgNumType fmt）——已在阶段 1 处理。
2. **keepNext 连锁**：阶段 4 轮次上限 2，超限报告。
3. **语义识别误判**：元素映射歧义必须问用户，不猜；verify 兜底。
4. **超大文档性能**：>150 页分节处理，进度可见。
5. **模板自身不规范**：众数+flag，异常交用户裁决，不污染规则。
